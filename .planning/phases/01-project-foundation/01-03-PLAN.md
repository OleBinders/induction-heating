## Tasks

<task>
<type>feature</type>
<description>Create pydantic schemas for material data validation</description>
<read_first>
- /home/olebinders/Documents/Code/Induction Heating/.planning/phases/01-project-foundation/01-RESEARCH.md
</read_first>
<acceptance_criteria>
- TemperatureDataPoint schema: temperature (float), value (float)
- TemperatureDependentProperty schema: data (list of TemperatureDataPoint), unit (str), temperature_unit (str)
- Material schema: name (str), category (str), density, curie_temperature (optional), resistivity (TemperatureDependentProperty), relative_permeability (TemperatureDependentProperty, optional)
- Pydantic v2 syntax (model_validate, not parse_obj)
</acceptance_criteria>
<verify>
- Valid JSON data loads without error via Material.model_validate()
- Invalid JSON data (missing fields, wrong types) raises ValidationError
- Curie temperature is optional (non-magnetic materials don't have it)
</verify>
</task>

<task>
<type>feature</type>
<description>Create material data files for 5 materials with temperature-dependent properties</description>
<read_first>
- /home/olebinders/Documents/Code/Induction Heating/.planning/phases/01-project-foundation/01-RESEARCH.md
</read_first>
<acceptance_criteria>
- Low carbon steel (AISI 1018): resistivity from 20°C to 1000°C, permeability with Curie point at 770°C
- Medium carbon steel: resistivity from 20°C to 1000°C, permeability with Curie point at 760°C
- Copper: resistivity from 20°C to 1000°C, no permeability (non-magnetic)
- Aluminum: resistivity from 20°C to 660°C, no permeability
- Brass (70/30): resistivity from 20°C to 500°C, no permeability
- All values in SI units (Ω·m for resistivity, °C for temperature)
</acceptance_criteria>
<verify>
- Each JSON file validates against the Material schema
- Resistivity values increase with temperature (physically correct)
- Steel permeability drops to 1.0 at and above Curie temperature
</verify>
</task>

<task>
<type>feature</type>
<description>Create MaterialDatabase with loading, querying, and interpolation</description>
<read_first>
- /home/olebinders/Documents/Code/Induction Heating/.planning/phases/01-project-foundation/01-RESEARCH.md
</read_first>
<acceptance_criteria>
- MaterialDatabase loads all JSON files from data/ directory on init
- get_material(name) returns Material by name (case-insensitive)
- list_materials() returns list of available material names
- get_property_at_temperature(material_name, property_name, temperature) returns interpolated value
- Uses PchipInterpolator for permeability (monotonicity-preserving, stays positive)
- Uses CubicSpline for resistivity (smooth interpolation)
- Raises ValueError when querying outside data temperature range (no extrapolation)
</acceptance_criteria>
<verify>
- Database loads all 5 materials
- get_material("low carbon steel") returns correct material
- get_property_at_temperature("low_carbon_steel", "resistivity", 350) returns value between data points
- get_property_at_temperature with temperature outside range raises ValueError
- list_materials() returns all 5 material names
</verify>
</task>

## Must Haves

**Truths:**
- Material library provides temperature-dependent resistivity for all 5 materials
- Interpolation works at arbitrary temperatures within data range
- Permeability stays positive and drops to 1.0 at Curie point

**Prohibitions:**
- MUST NOT extrapolate material properties outside data range
- MUST NOT use Pydantic v1 syntax (parse_obj) — use v2 (model_validate)
- MUST NOT allow negative permeability values from interpolation
